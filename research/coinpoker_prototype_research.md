# CoinPoker 三項互動功能的原型復刻調查

本報告供 CoinMahjong prototype 實作使用，範圍是頭像與外框、表情互動、遊戲內聊天。
核心操作、素材與客戶端狀態已足以建立本機互動原型。
線上會員資格、遠端功能開關及聊天限制，仍需以模擬資料呈現。

調查日期為 2026-10-04。客戶端基準為 macOS CoinPoker 1.27.0。
本次交付研究與素材索引，尚未把功能整合到麻將桌。

## 結果總覽

| 功能 | CoinPoker 中的角色 | 原型需要復刻的內容 |
| --- | --- | --- |
| 頭像與外框 | 玩家身分及狀態辨識。頭像可選，部分素材受會員資格限制。 | 分組選擇、目前選取、立即套用、鎖定提示，以及依玩家狀態顯示外框。 |
| 表情互動 | 自己座位的反應，以及從自己指向對手的投擲效果。 | 兩種入口、分類選單、最近使用、指定對象、動畫播放與關閉設定。 |
| 遊戲內聊天 | 桌內訊息歷史與座位旁的暫時泡泡。 | 抽屜收合、捲動、輸入、快速用語、回覆、複製、標記玩家與靜音設定。 |

建議先以桌面滑鼠操作為基準。
原始麻將草稿採固定舞台縮放，手機觸控入口需在實作時另作適配。
本次沒有把桌面 hover 行為當成已確認的手機操作。

### 如何判讀證據

- **畫面確認**：本輪在原生客戶端查看的 UI，或已核對的原生截圖。
- **程式確認**：客戶端程式、場景設定與原始素材支持的行為。尚不等於線上操作已實測。
- **官方說明**：CoinPoker 官網對使用者公開的功能說明。
- **原型建議**：為本機展示提出的模擬或適配方式。尚未成為使用者決議。

四個來源檔案的 SHA-256 均與既有素材清單一致。
新增證據也核對了 193 個方法的指令位置與操作碼。
詳細資料見 [客戶端證據](coinpoker_evidence.json)。

原生頭像設定頁已查看分類、預覽與會員鎖定。
原生牌桌已查看頭像、外框及聊天入口。
聊天圖示在本次工具操作下沒有展開，原因尚未確認。
本次未更換帳號頭像、入座、送出聊天或投擲。

[素材瀏覽頁](../coinpoker_assets/index.html)及其多數驗證截圖是本機重建示範。
它們可用於檢查素材，不能證明 CoinPoker 原生版面或線上行為。

## 頭像與外框

### UI 與功能位置

**畫面確認**：Settings 的 Avatars 頁有大型玩家預覽。
下方以主題分組排列圓形頭像，內容可垂直捲動。
較長的分類有左右切換按鈕。
目前選取項帶有勾選標記，會員專屬列會顯示鎖定遮罩。

| 分類 | 已取得素材數 | 可用性依據 |
| --- | --- | --- |
| 3-BET CLUB | 16 | 設定頁確認有此分類與鎖頭。實際解鎖依帳號資格。 |
| WORLD CUP | 10 | 設定頁確認此分類及橫向切換入口。 |
| ANIMAL | 5 | 設定頁確認。 |
| ANIME | 5 | 設定頁確認。 |
| HALLOWEEN | 5 | 設定頁確認。 |
| NOBLE | 5 | 設定頁確認。 |
| ROYAL | 5 | 設定頁確認。 |

原生牌桌將頭像、外框、暱稱與籌碼資訊組成座位識別區。
行動中的光效與計時條也出現在附近。
**原型建議**：只移植身分與互動相關元素，保留麻將既有分數、風位及回合資訊。

### 使用流程與狀態

| 使用者操作 | CoinPoker 行為 | 證據 |
| --- | --- | --- |
| 開啟 Settings → Avatars | 顯示目前玩家預覽及分組選單。 | 畫面確認。 |
| 捲動或切換分類列 | 查看其他頭像，不改變目前選取。 | 畫面與元件結構。 |
| 點可用頭像 | 更新選取狀態，立即呼叫套用與設定更新。 | `handleAvatarClick` 與 `onApply`。 |
| 點會員鎖定頭像 | 非會員走會員提示分支，不執行一般套用。 | 同一點擊處理函式。 |
| 返回牌桌 | 桌上依玩家頭像 ID 載入圖像，未設定時使用預設頭像。 | `PlayerAvatarStore.GetAvatar` 與 `PlayerComponent.SetAvatar`。 |
| 點牌桌上的對手頭像 | 開啟玩家資料與 HUD。 | 官方說明及 `HoverOnAvatar.OnPointerClick`。 |

程式證據顯示頭像選擇直接套用，無需自行增加儲存步驟。
本次未實際更換帳號頭像，因此未測量跨視窗更新延遲。

點頭像查看資料的入口，與投擲按鈕是不同操作。
**原型建議**：保留獨立投擲入口，避免將點整張頭像改成直接投擲。
完整撲克 HUD、玩家筆記與技術統計不列入本次三題的必要復刻內容。
官方入口依據見 [CoinPoker HUD 說明](https://coinpoker.com/help/heads-up-display/)。

### 外框的角色

[外框素材清單](../coinpoker_assets/catalog/rings.json)共有 26 個圖像檔。
其中包含 Unity 與 Electron 版本，也包含名次、Skill Score、直播及會員相關圖像。
這個數字不代表玩家可以任選 26 種外框。

**程式確認**：`AICPlayerComponent.ToggleAICStatus` 依會員狀態切換預設與會員外框。
玩家標記色另由 `PlayerComponent.UpdatePlayerOutline` 處理。
兩者應保持不同的資料欄位，不能把外框與任意標記色混為一談。

**原型建議**：以預設外框及 3-Bet Club 外框展示狀態差異。
其他名次、Skill Score 與直播外框保留於素材庫，待需要該展示情境時才加入。
真實 API 的完整外框優先順序仍未確認。
既有研究中的 API 方向屬原型決定，不是已取得的線上 API 契約。

### 素材與原型邊界

- [頭像索引](../coinpoker_assets/catalog/avatars.json)：51 張圖像，含 ID、分類、尺寸、來源與雜湊。
- [外框索引](../coinpoker_assets/catalog/rings.json)：各狀態圖像及版本來源。
- [UI 素材索引](prototype_asset_map.json)：原始會員鎖頭、會員標示與互動入口。

**原型建議**：選取後同步更新本人預覽、玩家列表與聊天訊息頭像。
以本機資料保存目前頭像，並提供一般與會員兩種測試身分。
會員提示只展示鎖定原因，不需要製作訂閱或付款流程。

## 表情互動

### 兩種不同的操作

| 類型 | 入口 | 對象 | 顯示方式 |
| --- | --- | --- | --- |
| 一般表情 | 自己座位的表情按鈕。 | 發送者本人。 | 在發送者座位的動畫容器播放。 |
| 投擲效果 | 對手座位旁的投擲按鈕。 | 選定的另一位玩家。 | 從發送者移動到目標，接續播放效果。 |

以上區分由 `PlayerEmojiButtonComponent`、`EmojiPanelComponent` 及 `ThrowablePopupComponent` 確認。
官方也將兩者分開描述，見 [3-Bet Club 功能說明](https://coinpoker.com/promotions/3-bet-club/)。

### 一般表情的選單與流程

**程式確認**：選單上方是可垂直捲動的表情網格。
下方是可水平捲動的分類圖示列。
分類順序由原始 `EmojisListCategoryWise` 指定。

| 分類 | 素材數 | 原始 ID |
| --- | --- | --- |
| Recents | 最多 10 筆引用 | 重用其他分類 ID，不新增動畫。 |
| Dogs | 10 | 56–65。 |
| Penguin | 7 | 41–47。 |
| Donkey | 5 | 22–26。 |
| Chips | 6 | 48–53。 |
| Skull | 8 | 1001–1008。 |
| Pepe | 5 | 5001–5005，程式列為會員鎖定內容。 |

41 個表情有完整素材，其中 36 個列於隨程式附帶的預設設定。
Pepe 的顯示還受會員功能開關影響。
素材存在不代表每個線上帳號都會看見或可以使用。

| 操作或事件 | 客戶端行為 |
| --- | --- |
| 點本人表情按鈕 | 開啟或關閉表情面板。 |
| 第一次開啟面板 | 優先選取最近使用之後的第一個分類。原始順序為 Dogs。 |
| 點分類 | 清除其他分類的選取，顯示該分類內容。 |
| 滑鼠移入素材 | 縮放至 1.0，轉場約 150 毫秒。 |
| 滑鼠移出素材 | 縮回 0.9，轉場約 150 毫秒。 |
| 點可用表情 | 發送 ID、更新 Recents、在本人座位播放，然後關閉面板。 |
| 重複使用同一表情 | 移到 Recents 最前面，不新增重複項。 |
| Recents 超過 10 筆 | 刪除最舊項，並更新使用者偏好。 |
| 點會員鎖定表情 | 顯示鎖定提示，不走一般播放分支。 |
| 收到他人的表情事件 | 依座位與表情 ID 播放。本人回送事件會被略過。 |
| 同一座位再次播放 | 播放器先清理該座位的既有動畫。 |
| 收到桌面中央活動事件 | 關閉表情面板。 |

依據為 [客戶端證據](coinpoker_evidence.json)內的 `EmojiPanelComponent`、`EmojiPlayableButton`、`Emoji` 與 `SkottieAnimationController`。
本輪未在入座狀態實際發送表情。

### 投擲的選單與流程

**程式確認**：本地玩家必須已入座，才走對手 hover 顯示投擲入口的路徑。
投擲選單會依目標座位位置調整方向，並使用指向目標的箭頭。

| 操作或條件 | 客戶端行為 |
| --- | --- |
| 滑鼠移入對手座位 | 開啟 hover 設定時，等待約 250 毫秒顯示按鈕。 |
| 等待完成前移出 | 取消顯示排程。 |
| 滑鼠移出對手座位 | 在 hover 模式下隱藏按鈕。 |
| 關閉 Show throwables on hover | 已入座時，對手投擲按鈕維持顯示。 |
| 點對手的投擲按鈕 | 記住該玩家，將選單放到適當位置。 |
| 點可用投擲素材 | 關閉選單，確認來源與目標仍存在，再送出事件及本機播放。 |
| 點會員鎖定投擲素材 | 顯示資格提示。 |
| 來源或目標已不存在 | 結束處理，不播放到錯誤座位。 |
| 停用投擲效果 | 接收事件時不播放。設定說明也表示他人不能對自己投擲。 |
| 收到本人發出的回送事件 | 略過，避免本機動畫重複。 |

相關設定頁有原生截圖可參考：[投擲設定](../coinpoker_assets/verification/throwable_settings.jpg)。
其文案與本輪原生可及性資料一致。

共有 21 個投擲動畫，17 個列於附帶預設設定。
另外 4 個會員素材為水槍、驢子、碎牌與魚，ID 為 4001–4004。
完整順序與縮圖見 [原始投擲資料](../coinpoker_assets/catalog/unity/throwables.json)。

### 素材與原型邊界

已取得表情 41 組、投擲 21 組及其縮圖。
本次再補入原始投擲入口、分類高亮、Recents 與會員標記等 13 個 UI 圖像。
索引同時引用 8 個原先已存在的 UI 圖像，避免重複保存。

其餘 42 個動畫雖有播放 ID，但未找到目前選單入口。
**原型建議**：預設選單使用已確認的分類素材。
會員素材以鎖定與已解鎖兩種測試狀態呈現。
未列入選單的 42 個動畫先保留，不自行賦予牌局觸發條件。

冷卻時間、發送頻率限制，以及所有素材在即時服務中的可用性尚未確認。
這些項目不能從素材存在或動畫長度推導。

## 遊戲內聊天

### UI 結構

**畫面確認**：桌面版牌桌左下有聊天入口。
**程式確認**：點入口呼叫 `ShowChatPanel`，顯示左側滑入的聊天區。

| 區域 | 需要的 UI 元素 |
| --- | --- |
| 訊息歷史 | 可捲動區、自身與他人訊息、頭像、暱稱、文字、時間。 |
| 回覆內容 | 原作者與被引用文字，出現在回覆訊息及輸入前的引用區。 |
| 輸入區 | Type here.. 提示、文字輸入、送出按鈕、`@` 玩家入口。 |
| 快速用語 | 橫向常用語列，以及可展開的用語面板。 |
| 訊息操作 | 滑鼠移入後出現操作按鈕，再開啟 Reply 與 Copy。 |
| 選項 | Mute spectator chat、Hide chat bubbles、Mute all chats。 |
| 空狀態 | Start Chatting。 |
| 錯誤狀態 | 歷史區中的錯誤提示樣式。 |
| 桌上泡泡 | 靠近說話者座位的暫時文字泡泡。 |

聊天場景保留了自身與他人兩種訊息元件。
**原型建議**：維持辨識差異，使用原始圖像與麻將既有文字樣式協調版面。
原始抽屜背景約 295 設計單位寬，位移參數為 -300 到 0。
這些數字不能直接當作各種螢幕下的 CSS 像素。

來源見 [聊天場景結構](../coinpoker_assets/chat/scene_structure.json)及 [原始文案](../coinpoker_assets/chat/english.json)。

### 開啟與送出流程

| 操作或事件 | 客戶端行為 |
| --- | --- |
| 開啟聊天 | 清除回覆引用，關閉快速用語、選項與玩家名單等子面板。 |
| 抽屜滑入 | 約 150 毫秒。同次開啟會刷新空狀態並聚焦輸入欄位。 |
| 開啟或收到訊息 | 約 50 毫秒後將捲動位置設到最新訊息端。 |
| 輸入文字後點送出 | 送出 TEXT 類型資料。 |
| 按 Enter | 呼叫同一送出函式。 |
| 文字為空或只有空白 | 不發送訊息。 |
| 收到本人訊息 | 加入自身訊息元件，清空輸入。 |
| 收到他人訊息 | 加入他人訊息元件，不清空本人正在輸入的文字。 |
| 關閉抽屜 | 約 100 毫秒，收起子面板並清除回覆引用。 |
| 收到桌面中央活動事件 | 收起聊天區。 |

依據為 `TableMenuController.OnChatBtnClick` 及 `ChatPanelComponent`。
客戶端在收到本人訊息時才清空輸入，不能把程式確認描述成已完成線上送出實測。

輸入元件是 `CustomNPInputField`。
場景中的 `m_CharacterLimit` 為 0，未設定固定字數上限。
伺服器是否限制訊息長度仍未知。

### 快速用語與訊息操作

| 功能 | 流程與狀態 |
| --- | --- |
| 快速用語 | 點選後直接送出，關閉展開面板，再聚焦輸入欄位。不是只填入草稿。 |
| 回覆 | 訊息 hover → 操作按鈕 → Reply → 顯示原作者及文字 → 輸入 → 送出引用資料。 |
| 取消回覆 | 關閉引用區，清除引用資料，恢復一般輸入。 |
| 複製 | 訊息操作選單 → Copy → 複製該則訊息文字。 |
| `@` 玩家 | 開啟玩家名單，選擇後把輸入設為 `@玩家名 `，並聚焦游標。 |
| 訊息 hover 結束 | 隱藏操作按鈕與 Copy／Reply 面板。 |
| 點選項面板外部 | 收起該面板。 |

`TagToUser` 是覆寫輸入文字，不是已確認的任意游標位置補字功能。
若原型改成保留原稿並插入標記，應另記為產品調整。

快速用語設定有 8 個翻譯鍵。
現有語系只確認 `GG 👍` 與 `Fishy AF 🐠🐡` 兩個實際字串。
其餘 6 個字串不能用自行編寫的內容冒充原生清單。
**原型建議**：先展示兩個有來源的用語，或明示增加的是麻將原型文案。

依據見 [聊天行為摘要](../coinpoker_assets/chat/behavior.json)、[快速用語設定](../coinpoker_assets/catalog/chatConfig.json)及 [客戶端證據](coinpoker_evidence.json)。

### 設定與座位泡泡

| 設定或事件 | 確認行為 | 原型呈現方式 |
| --- | --- | --- |
| Mute spectator chat | 設定值會保存並傳送到牌桌。官方說明為靜音觀戰者。 | 用帶有 spectator 身分的模擬訊息驗證過濾。 |
| Hide chat bubbles | `GameModal.ShowChatMessage` 保留訊息歷史，但跳過座位泡泡。 | 新訊息仍進歷史，桌上不顯示泡泡。 |
| Mute all chats | 客戶端略過其他人的新訊息。與本人帳號名稱相符的訊息仍可進歷史。 | 不把它實作成關閉聊天面板或停用本人輸入。 |
| 新聊天訊息 | 需訊息帶有 `chatBubble` 條件，且未隱藏泡泡，才顯示桌上泡泡。 | 模擬資料保留該旗標。 |
| 泡泡出現 | 依座位位置調整，縮放動畫約 100 毫秒。 | 四人與三人桌分別對應座位。 |
| 泡泡到期 | 約 3 秒後隱藏。新泡泡會重設該座位的隱藏排程。 | 同一座位只維持目前泡泡。 |

靜音觀戰者的本機接收過濾分支未在本輪選定方法中找到。
其使用者行為有官方說明支持，但線上過濾位置仍未知。
三個設定的官方入口見 [遊戲介面 FAQ](https://coinpoker.com/fr/help/gameplay-navigation-faq/)。

原始場景有全下時聊天停用的錯誤示例，也有錯誤訊息處理程式。
這不表示本輪已驗證該規則在每種牌桌都啟用。
**原型建議**：保留通用錯誤顯示能力，不把撲克全下規則套到麻將。

## 移植到麻將草稿的最小方案

以下是依研究提出的實作建議，並非已完成的修改。

### 座位與版面

[麻將草稿](../mahjong-game-standalone.html)使用 1440 × 1024 的固定舞台，隨視窗等比縮放。
玩家頭像與分數集中在右側的 `player-info-0` 到 `player-info-3`。
中央桌面沒有 CoinPoker 那種環桌頭像座位卡。

**建議方案**：保留右側玩家資訊，同時建立固定的玩家與桌上座位對應。
表情、泡泡與投擲終點使用桌上座位的顯示位置。
選取對手時，右側玩家列與目標位置需有一致回饋。
這能保留指向某人的互動含義，避免投擲只在右側列表上下移動。

三人桌會隱藏 `data-seat="3"` 的元素。
等待狀態也會隱藏尚未入座的玩家列。
互動目標必須依當下有效座位建立，不能固定假設永遠有四名玩家。

聊天可沿用左側抽屜概念，但需避開手牌與操作區。
這是麻將版面適配，最終位置仍需在實作畫面核對。
表情動畫層應讓滑鼠事件穿透，選單與聊天輸入區則保留操作。

## 尚未確認及其影響

| 缺口 | 對原型的影響 | 建議處理 |
